# 📖 Глава 2: Накопители (NVMe, SSD, HDD), Шины (PCIe, USB) и Дерево устройств `/dev`

> **Для кого эта глава:** Для начинающих системных администраторов, которые хотят понять, как устроены современные диски, почему NVMe в 10 раз быстрее SATA, как процессор общается с железками через шину PCIe, и как Linux превращает диски и флешки в файлы `/dev/sda` и `/dev/nvme0n1`.

---

## 🧭 Введение: Как данные попадают в процессор?

В прошлой главе мы выяснили, что процессор и оперативная память работают молниеносно. Но у оперативной памяти есть один фатальный недостаток: **при выключении питания всё содержимое RAM мгновенно стирается**.

Чтобы операционная система, базы данных и файлы сохранялись навсегда, нужны **энергонезависимые накопители (Storage)**.

Но как эти накопители подключаются к процессору? По каким «дорогам» бегут данные? Разберёмся по порядку.

---

## 💾 ЧАСТЬ 1. Эволюция накопителей: HDD vs SATA SSD vs NVMe SSD

```text
               [ Процессор (CPU) ]
                        |
            +-----------+-----------+ (Шина PCIe Gen 4/5 — Автобан 7000 МБ/с)
            |                       |
     [ Видеокарта ]           [ NVMe SSD M.2 ] (Прямое подключение к CPU)
                                    |
                            [ Чипсет платы ]
                                    |
                    +---------------+---------------+ (Шина SATA III — Проселочная дорога 550 МБ/с)
                    |                               |
             [ SATA SSD 2.5" ]                [ HDD 3.5" ]
```

---

### 1. HDD (Hard Disk Drive — Жесткий диск)
- **Как устроен внутри:** Внутри герметичного корпуса с бешеной скоростью (5400, 7200 или 10 000 оборотов в минуту) вращаются металлические магнитные «блины». Над ними на микроскопическом расстоянии летает механическая считывающая головка.
- **Главная проблема HDD (IOPS и Задержка):**  
  Чтобы прочитать файл, головка должна физически долететь до нужной дорожки на вращающемся диске. Это занимает **10–15 миллисекунд** (в компьютерном мире это целая вечность!).
  - *Количество операций ввода-вывода в секунду (IOPS):* всего **75–150 IOPS**.
- **Где используется сегодня:** Для дешевого архивного хранения огромных массивов данных (бэкапы, видеозаписи, файловые хранилища).

---

### 2. SATA SSD (Solid State Drive — Твердотельный накопитель)
- **Как устроен внутри:** Никакой механики! Внутри находятся кремниевые чипы флеш-памяти (**NAND Flash**) и микроконтроллер.
- **Преимущество:** Время доступа к любому файлу — **~0.1 миллисекунды** (в 100 раз быстрее HDD!).
- **Узкое горлышко (Интерфейс SATA III):**  
  SATA-кабель разрабатывался еще для старых жестких дисков. Его физический предел скорости — **~550–600 МБ/с**. Флеш-память может работать быстрее, но SATA-провод просто не способен пропустить больше данных.

---

### 3. NVMe SSD (Non-Volatile Memory Express)
- **Революция:** Инженеры решили: *«Зачем подключать быстрый SSD через медленный кабель SATA к чипсету? Давайте воткнем SSD напрямую в шину процессора — PCIe!»*
- **Форм-фактор M.2 / U.2 / E1.S:** Небольшая плата, вставляемая прямо в слот материнской платы.
- **Скорость:** **3500 – 7500+ МБ/с** (в 10–15 раз быстрее обычного SATA SSD!).
- **Параллелизм:** Протокол NVMe поддерживает до **64 000 очередей команд** одновременно (у старого SATA была всего 1 очередь на 32 команды).
- **Где используется:** Стандарт для современных серверов, баз данных и рабочих станций.

---

## 🛣️ ЧАСТЬ 2. Шины материнской платы: PCIe и USB

Чтобы процессор мог управлять сетевой картой, видеокартой или диском, на плате проложены скоростные цифровые магистрали — **Шины (Buses)**.

---

### 1. Шина PCIe (Peripheral Component Interconnect Express)
Это главная внутренняя скоростная магистраль компьютера.
- **Линии PCIe (Lanes):** Данные передаются по параллельным линиям, обозначаемым буквой `x`:
  - `x1` — звуковые карты, простые сетевые адаптеры.
  - `x4` — NVMe накопители (M.2 слот обычно имеет 4 линии PCIe).
  - `x8` / `x16` — видеокарты и сверхбыстрые серверные сетевые карты (10G/40G/100G).
- **Поколения (Generations):**
  - PCIe 3.0: ~1 ГБ/с на одну линию `x1`
  - PCIe 4.0: ~2 ГБ/с на одну линию `x1` (для слота `x4` это ~8 ГБ/с)
  - PCIe 5.0: ~4 ГБ/с на одну линию `x1`

#### Как администратор смотрит шину PCIe: команда `lspci`
Утилита `lspci` (List PCI) выводит список всех устройств, подключенных к шине PCI/PCIe:
```bash
lspci
```
Пример вывода:
```text
00:00.0 Host bridge: Intel Corporation ...
00:02.0 VGA compatible controller: Intel Corporation ...
01:00.0 Non-Volatile memory controller: Samsung Electronics NVMe SSD Controller
02:00.0 Network controller: Intel Corporation Wi-Fi 6 AX200
```
> 💡 *Полезный флаг:* `lspci -v` (подробно) или `lspci -k` (показывает, какой драйвер/модуль ядра управляет каждым устройством).

---

### 2. Шина USB: команда `lsusb`
Для внешних периферийных устройств используется утилита `lsusb` (List USB):
```bash
lsusb
```
Она показывает все подключенные мыши, клавиатуры, внешние диски, флешки и веб-камеры.

## 🌲 ЧАСТЬ 3. «Всё есть файл» — Дерево устройств `/dev`

В Linux действует фундаментальный принцип UNIX-систем:  
> 🌟 **«Everything is a file» (Всё есть файл).**

В Linux нет концепции дисков `C:`, `D:`, `E:`. Любое аппаратное устройство представлено специальным файлом в каталоге `/dev` (devices).

---

### Как Linux называет накопители в `/dev`?

| Префикс в `/dev` | Тип оборудования | Пример имени диска | Пример имени раздела 1 |
| :--- | :--- | :--- | :--- |
| **`/dev/sdX`** | **S**CSI / S**A**TA диски (SATA SSD, HDD, USB-флешки) | `/dev/sda` (диск 1), `/dev/sdb` (диск 2) | `/dev/sda1`, `/dev/sdb1` |
| **`/dev/nvmeXnY`** | **NVMe** накопители (M.2 PCIe SSD) | `/dev/nvme0n1` (накопитель 0, пространство 1) | `/dev/nvme0n1p1` (`p1` = partition 1) |
| **`/dev/mmcblkX`** | Карты памяти SD, MicroSD и eMMC чипы | `/dev/mmcblk0` | `/dev/mmcblk0p1` |

---

### Главный инструмент дискового администратора: `lsblk`

Команда `lsblk` (List Block Devices) рисует наглядное дерево всех накопителей, их разделов и точек монтирования:

```bash
lsblk -f
```

Пример вывода:
```text
NAME        FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
nvme0n1                                                                            
├─nvme0n1p1 vfat   FAT32       1234-ABCD                             500M     2% /boot/efi
├─nvme0n1p2 ext4   1.0         a1b2c3d4-e5f6-...                    45.2G    48% /
└─nvme0n1p3 swap   1           9876-5432-...                                     [SWAP]
```

- **`NAME`:** Имя диска (`nvme0n1`) и его разделов (`p1`, `p2`, `p3`).
- **`FSTYPE`:** Файловая система (ext4, vfat, xfs, btrfs, swap).
- **`UUID`:** Уникальный идентификатор раздела (по нему Linux находит диск при загрузке в файле `/etc/fstab`).
- **`MOUNTPOINTS`:** Куда в единое дерево каталогов подключен этот раздел (`/`, `/boot`, `[SWAP]`).

## 🩺 ЧАСТЬ 4. Здоровье накопителей: S.M.A.R.T. диагностика

Накопители — это расходный материал. Флеш-память SSD со временем изнашивается от постоянных перезаписей (ячейки памяти выдерживают ограниченное число циклов стирания), а у HDD изнашивается механика и появляются «битые секторы» (Bad Sectors).

Чтобы жесткий диск или SSD не умер внезапно вместе с базой данных компании, в каждый накопитель встроена система самодиагностики — **S.M.A.R.T.** (Self-Monitoring, Analysis and Reporting Technology).

---

### Утилита `smartctl`: Как читать здоровье диска

Для работы со SMART в Linux используется утилита `smartctl` (из пакета `smartmontools`).

#### 1. Быстрая проверка статуса здоровья (Health Status):
```bash
sudo smartctl -H /dev/nvme0n1   # (или /dev/sda)
```
- Если результат: `PASSED` / `OK` — критических сбоев контроллер пока не видит.

#### 2. Полный отчет по диску:
```bash
sudo smartctl -a /dev/nvme0n1
```

#### На какие параметры SMART смотреть админу?
1. **Для NVMe / SSD:**
   - **`Percentage Used` (или `Wear Range Delta`):** Сколько процентов ресурса флеш-памяти уже израсходовано (например, 3% = диск как новенький, 95% = срочно заказываем новый диск на замену!).
   - **`Data Units Written` (TBW — Terabytes Written):** Сколько всего терабайт данных было записано на этот диск за всю его жизнь.
   - **`Temperature`:** Температура накопителя (NVMe SSD сильно греются при нагрузке, критично держать ниже 70°C).
   - **`Media and Data Integrity Errors`:** Ошибки целостности ячеек памяти. В идеале должно быть строго `0`.

2. **Для классических HDD:**
   - **`Reallocated Sector Count` (Переназначенные секторы):** Количество сбойных секторов, которые диск перенес в резервную зону. Если это число больше 0 и растет — диск «сыпется», его пора менять.
   - **`Power_On_Hours`:** Сколько часов непрерывно проработал диск.

## 🛠️ Шпаргалка по командам главы

| Команда | Что делает |
| :--- | :--- |
| `lspci` | Список всех устройств на шине PCI Express (видеокарты, сетевые адаптеры, NVMe) |
| `lspci -k` | Показывает устройства PCI и драйверы ядра (Kernel driver in use), управляющие ими |
| `lsusb` | Список всех USB-контроллеров и подключенных USB-устройств |
| `lsblk` | Дерево накопителей, разделов, размеров и точек монтирования |
| `lsblk -f` | Дерево дисков с файловыми системами (FSTYPE) и UUID |
| `sudo smartctl -H /dev/...` | Быстрая проверка здоровья накопителя (PASSED / FAILED) |
| `sudo smartctl -a /dev/...` | Полный паспорт и все атрибуты износа/ошибок диска |

# Задание №2: Исследование процессора, памяти и подсистемы Linux

> 📘 **Учебник к этому заданию:**  
> Перед выполнением обязательно прочитай [Главу 1: Железо и Память для начинающих](../handbook/01_hardware_and_memory.md). Там простым языком на примерах объяснено всё устройство процессора, кэшей, памяти, команды `free` и подкачки.

---

## 🎯 Практические задачи

Все файлы создавай внутри папки `workspace/task2_hardware/`.

Если папка еще не создана:
```bash
mkdir -p ~/projects/linux-sysadmin-learning/workspace/task2_hardware
cd ~/projects/linux-sysadmin-learning/workspace/task2_hardware
```

---

### Задача 1: Паспорт процессора (`system_cpu.txt`)
1. Выполни команду `lscpu` и перенаправь её вывод в файл:
   `workspace/task2_hardware/system_cpu.txt`
2. Открой получившийся файл или посмотри его в терминале и найди:
   - Как называется твой процессор (`Model name`)?
   - Сколько у него ядер и сколько потоков (`Core(s) per socket`, `Thread(s) per core`)?
   - Каковы размеры кэшей `L1d`, `L1i`, `L2`, `L3`?
   - Включена ли аппаратная виртуализация (`Virtualization`)?

---

### Задача 2: Паспорт оперативной памяти (`ram_hardware.txt`)
1. Узнай информацию о физических планках RAM:
   - Если есть права sudo, выполни: `sudo dmidecode -t memory > ram_hardware.txt`
   - Если работаешь без sudo (или в WSL/контейнере), выполни: `lshw -C memory > ram_hardware.txt` (или скопируй вывод `cat /proc/meminfo > ram_hardware.txt`).
2. Посмотри в файле:
   - Какой тип памяти установлен (DDR4 / DDR5 / LPDDR)?
   - Какой объем у планок и сколько слотов свободно/занято?

---

### Задача 3: Анализ распределения памяти (`memory_analysis.txt`)
Собери в один файл `workspace/task2_hardware/memory_analysis.txt` три показателя:
1. Вывод команды `free -h`
2. Значение `swappiness` (команда `cat /proc/sys/vm/swappiness`)
3. Подробную информацию из `/proc/meminfo`

> 💡 *Подсказка:* Чтобы записать несколько команд в один файл, первую команду пиши с `>`, а следующие — с `>>` (дописывание в конец).

---

### Задача 4: Замер активности подкачки (`vmstat_report.txt`)
1. Выполни замер виртуальной памяти утилитой `vmstat`:
   Сделай 5 замеров с интервалом в 1 секунду и сохрани в `workspace/task2_hardware/vmstat_report.txt`.
2. Посмотри на столбцы `si` (swap-in) и `so` (swap-out).

---

### Задача 5: Отчет ученика своими словами (`HARDWARE_REPORT.txt`)
Создай файл `workspace/task2_hardware/HARDWARE_REPORT.txt` и кратко, своими словами (как понял из учебника) ответь на 5 вопросов:
1. Зачем процессору нужны кэши L1, L2, L3 и почему нельзя сразу всё читать из оперативной памяти (RAM)?
2. Зачем нужен флаг виртуализации `vmx` (или `svm`) процессора?
3. Почему когда в команде `free -h` колонка `free` показывает мало памяти, это НЕ значит, что памяти не хватает? На какую колонку нужно смотреть?
4. Что такое `swappiness` и почему для баз данных его значение обычно снижают до `1`–`10`?
5. Что делает ядро Linux (OOM Killer), когда оперативная память и Swap полностью заполняются?
